System Architecture · RAG Insurance Assistant

Coverage Chatbot, end to end

A member asks a plan or claims question in the Streamlit UI. It flows through a FastAPI backend, gets routed to structured SQL lookups, vector retrieval, or both, gets grounded and generated by a local Ollama model, and comes back with citations and structured cards — while guardrails, PII redaction, and Langfuse tracing watch every hop.

Client

Streamlit

The member-facing chat surface. Streams tokens as they generate, renders structured claim/plan cards, and keeps a session id alive for the length of the browser tab.

POST /chat and /chat/stream, JSON over HTTP
02

API & Orchestration

FastAPI

Owns the request lifecycle: rate limiting, cache lookup, memory loading, plan inference, and stitching the retrieval + generation result into a response.

classify_question() routes to SQL, vector search, or both
03

Retrieval & Agents

LangGraph · MCP

The reasoning core. A deterministic router decides structured vs. unstructured vs. both, an optional multi-agent graph delegates to specialists, and tool calls travel over a real MCP server rather than in-process calls.

queries hit vectors, rows, and the model in parallel
04

Data & Model

ChromaDB · SQLite · Ollama

Where facts live. Policy text as embeddings, plans/claims/conversations as relational rows, and a locally-hosted LLM that never leaves the machine.
